- [[Real World Event Sourcing]]
	- 01. Building Your First Event-Sourced Application
		- The fundamental idea of Event Sourcing is that of ensuring every change to the state of an application is captured in an event object, and that these event objects are themselves stored in the sequence they were applied for the same lifetime as the application state itself
			- 이벤트 소싱은 매 변화를 이벤트 오브젝트에 저장하고, 이 오브젝트들은 상태에 적용되었던 순서대로 보관된다.
		- Event sourcing is all about deriving meaningful state from the past.
			- 과거에서부터 의미있는 상태를 유도하는 것이 이벤트 소싱의 전부다.
		- One of the most common objections to event sourcing, that it requires too much boilerplate, stems from looking at solving trivial problems.
			- 이벤트 소싱에 대한 가장 흔한 관점은, 하찮은 문제를 풀기위해 너무 많은 보일러 플레이트 코드가 필요하다는 것이다.
		- Events
			- 불변이고 과거형이다.
			- 실패 이벤트의 적용은 항상 이전 상태를 반환한다.
		- Aggregates
			- 식별자를 가지는 단일 엔티티다.
			- 입력 커맨드를 검사하고 이벤트들을 출력한다.
			- 이전 상태에 이벤트를 적용해 다음 상태를 생성한다.
			- 이벤트와 커맨드의 적용은 순수하고 참조 투명하다.
